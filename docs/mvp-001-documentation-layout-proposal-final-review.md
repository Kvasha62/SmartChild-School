## 3. Существенное замечание

### FR-01 · Существенное · Раздел 2, строка 58; раздел 2.1, строки 84—88

**Проблема.** Утверждение раздела 2 о единственном совпадении имён файлов ложно на опубликованном HEAD `a7b6f4e…`.

**Цитата (раздел 2, строка 58):**

> До добавления настоящего документа в истории репозитория **не существовало ни одного файла** с именем, содержащим `review`, `report`, `ревиз`, `предложен`, `отчёт`. По шаблону `proposal` совпадений не было до появления настоящего файла: во всех деревьях истории, включая текущее, единственное совпадение с указанными шаблонами — сам документ `docs/mvp-001-documentation-layout-proposal.md`.

**Доказательство.** Раздел 2.1 (строки 84—88) приводит команду проверки:

```bash
for c in $(git rev-list e192275560ac0e67f003bd520aab5ad37f265aa7); do
  git ls-tree -r --name-only "$c"
done | sort -u | grep -iE 'review|proposal|report|ревиз|предложен|отчёт'
# → единственное совпадение: docs/mvp-001-documentation-layout-proposal.md
```

Команда привязана к исходному SHA `e192275…`, а вывод в документе заявлен как относящийся ко «всем деревьям истории, включая текущее». Фактическое выполнение:

| Точка отсчёта | Уникальных путей | Совпадений | Результат |
| --- | --- | --- | --- |
| `e192275…` (как в документе) | 11 | **1** | `docs/mvp-001-documentation-layout-proposal.md` |
| `a7b6f4e…` (опубликованный HEAD) | 12 | **2** | `docs/mvp-001-documentation-layout-proposal-review-response.md` и `docs/mvp-001-documentation-layout-proposal.md` |

Второе совпадение появилось потому, что тот же PR добавил отчёт об устранении замечаний, в имени которого есть `review`.

**Последствия.** Документ, предмет которого — достоверное описание состояния репозитория, содержит утверждение, опровергаемое его же собственной командой проверки при выполнении на текущем HEAD. Читатель, выполнивший команду из раздела 2.1 с `HEAD` вместо устаревшего SHA, получит две строки и обнаружит противоречие. Это в точности тот дефект, который был зафиксирован как RC-02: вывод, истинный для прошлого состояния, сформулирован так, что читается как актуальный факт. Следовательно **RC-02 на опубликованном SHA не устранён**.

**Рекомендуемое действие.** Одно из двух:

1. Привести утверждение к фактическому состоянию текущего дерева: указать, что на момент публикации совпадений два — сам документ и отчёт об устранении замечаний, — и что оба добавлены этим PR.
2. Либо сузить границу времени до коммита `e192275…` и дополнительно привести отдельную явную сводку для текущего HEAD.

В обоих случаях заменить в команде раздела 2.1 закреплённый старый SHA на `HEAD` (или явно указать оба SHA) и обновить ожидаемый вывод под фактический результат.

**Критерий устранения.** Выполнение команды из раздела 2.1 с `HEAD` даёт вывод, совпадающий с заявленным в документе числом совпадений.

## 4. Незначительные замечания

### FR-02 · Незначительное · Раздел 2.1, строка 91

**Проблема.** Фраза «в мелкой копие `git rev-list --count HEAD` даёт 1 вместо 11» смешивает точки отсчёта и содержит опечатку.

**Доказательство.** Наблюдение сделано при HEAD = `280f903…`; полное число коммитов, достижимых из этой точки, равно **10**, а не 11 (`git rev-list --count 280f903…` → 10). Число 11 относится к другой точке — `main` `f0253e54…`. Смешение точек отсчёта — то, против чего раздел 2.1 сам предостерегает в рамках RC-01. Опечатка: «в мелкой копие» вместо «в мелкой копии».

**Последствия.** Основная таблица раздела 2.1 корректна, поэтому влияние ограничено пояснительным предложением; однако оно прямо подрывает собственный методический вывод документа.

**Рекомендуемое действие.** Указать точку отсчёта явно, например: «при HEAD `280f903…` мелкий клон давал 1 вместо 10; из `main` `f0253e54…` — 11». Исправить опечатку.

### FR-03 · Незначительное · Отчёт об устранении, строки 31 и 93

**Проблема.** Отчёт об устранении оценивает RC-02 как «исправлено полностью» и подтверждает это сканом, выполненным по исходному HEAD, а не по опубликованному.

**Доказательство.** Строка 31: проверка RC-02 — команда `for c in $(git rev-list e192275…)` → «ровно одна строка». Строка 93: «единственное совпадение имён — сам документ». Обе проверки исключают файлы, добавленные коммитами исправлений, то есть не покрывают опубликованное состояние (см. FR-01).

**Последствия.** Отчёт содержит неверную оценку готовности по одному из трёх обязательных замечаний. Влияние ограничено отчётом, но оно маскирует FR-01.

**Рекомендуемое действие.** После устранения FR-01 перепроверить и обновить обе строки, указав точку отсчёта скана.

### FR-04 · Низкое · Раздел 4.4, строка 210

**Проблема.** Утверждение «каталог для независимых ревью в репозитории отсутствует, и исторически таких файлов не было» соседствует с файлом, добавленным этим же PR, в имени которого есть `review`.

**Доказательство.** Формулировка ограничена словом «исторически» и буквально остаётся истинной: добавленный файл — отчёт об устранении замечаний, а не независимое ревью, и размещён плоско в `docs/`, а не в каталоге ревью. Тем не менее читатель, видящий в том же PR файл с `review` в имени, может воспринять утверждение как противоречащее составу PR.

**Рекомендуемое действие.** Явно датировать утверждение, например: «до публикации настоящего PR файлов независимых ревью в репозитории не было».

### FR-05 · Низкое · Заголовок, строка 4, против раздела 8, строка 329

**Проблема.** Заголовок сообщает: «Редакция: 2 — устранены замечания RC-01—RC-03». Раздел 8 сообщает: «Документ исправлен по RC-01—RC-03 и C-01—C-05».

**Последствия.** Минимальные: заголовок не отрицает работу по C-замечаниям, но расхождение в объёме заявленного между шапкой и итоговым разделом заметно.

**Рекомендуемое действие.** Привести формулировки к единому виду.
