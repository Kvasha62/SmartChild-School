## 2. Метод проверки и команды

Проверка выполнена на полной истории: `git fetch --unshallow origin`, `git rev-parse --is-shallow-repository` → `false`.

```bash
# объём истории
git rev-list --count f0253e54dfdbc8e5ce47679ef2c4cfc7adcbc4cf
git rev-list --count e192275560ac0e67f003bd520aab5ad37f265aa7

# команда из раздела 2.1 проверяемого документа (дословно)
SHA=$(git rev-parse HEAD)
git rev-parse --is-shallow-repository
for c in $(git rev-list "$SHA"); do
  git ls-tree -r --name-only "$c"
done | sort -u > /tmp/paths.txt
echo "путей: $(wc -l < /tmp/paths.txt)"
echo "совпадений: $(grep -icE 'review|proposal|report|ревиз|предложен|отчёт' /tmp/paths.txt)"
grep -iE 'review|proposal|report|ревиз|предложен|отчёт' /tmp/paths.txt
```

Дополнительно выполнено:

- скан по **каждому шаблону отдельно** (`review`, `proposal`, `report`, `ревиз`, `предложен`, `отчёт`) — не только по их объединению;
- сверка **фактических путей**, а не только чисел;
- проверка инварианта раздела 2 по деревьям, предшествующим `e192275…`;
- проверка параметров коммита `f0253e54…`, дерева `docs/` и числа строк документов на контрольном SHA;
- проверка реестров `docs/product-scope.md`;
- сплошной поиск утверждений о состоянии Git и о числе файлов;
- проверка ссылок, относительных целей и множеств идентификаторов ссылок.

### Проверки, которые невозможно выполнить

1. **Автоматические проверки репозитория.** В проекте нет приложения, сборки, тестов и workflow CI (`CONTRIBUTING.md`, раздел «Проверки документационного PR»). Ни одна проверка не пройдена; успешное прохождение не заявляется.
2. **Воспроизведение исходного мелкого состояния.** `git rev-parse --is-shallow-repository` → `true` относилось к исходной рабочей копии; после раскрытия клона команда возвращает `false`.
3. **Состояние внешних артефактов.** Файлы `MVP-001-starter-content-proposal-v2.md` и `MVP-001-starter-content-proposal-v2-independent-review.md` находятся вне репозитория, в текущей рабочей среде отсутствуют и по коммиту не проверяемы. Утверждения раздела 6 о них приняты как снимок состояния (см. TR-03).
4. **Собственный SHA отчёта.** Итоговый HEAD коммита, добавившего настоящий отчёт, подтверждается после публикации командой `git rev-parse HEAD`.
