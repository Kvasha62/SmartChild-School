## 2. Причина регрессии

Вторая редакция документа устраняла RC-02 формулировкой, привязанной к **содержимому дерева**:

> во всех деревьях истории, включая текущее, единственное совпадение с указанными шаблонами — сам документ

Формулировка стала ложной, когда тот же PR добавил отчёт об устранении замечаний, в имени которого есть `review`. Ошибка носила не количественный, а **логический** характер: вывод о множестве объектов делался как абсолютный, хотя он зависит от того, какие файлы уже добавлены. Команда проверки в разделе 2.1 была закреплена за исходным SHA `e192275…` и потому не могла обнаружить расхождение.

Исправление поэтому не сводится к замене числа 1 на 2: изменён сам способ описания — результат теперь является функцией контрольного SHA, а команда параметризована.

## 4. Новая логика проверки имён файлов

### 4.1. Что именно изменено

1. **Отказ от абсолютных утверждений о содержимом дерева.** Вместо «единственное совпадение» — «число совпадений зависит от контрольного SHA».
2. **Инвариант, не зависящий от правок.** Утверждение об отсутствии совпадающих имён ограничено коммитами, предшествующими `e192275…`. Такое утверждение остаётся истинным при любых последующих добавлениях файлов.
3. **Параметризованная команда.** Вместо закреплённого SHA — переменная `SHA`, задаваемая явно.
4. **Таблица результатов по контрольным SHA** с указанием числа уникальных путей, числа совпадений и самих путей.
5. **Три правила пересчёта**, делающие регрессию невозможной при следующей документационной правке.

### 4.2. Команда

```bash
SHA=$(git rev-parse HEAD)                 # либо задайте контрольный SHA явно
git rev-parse --is-shallow-repository     # → false; до раскрытия клона проверка недостоверна
for c in $(git rev-list "$SHA"); do
  git ls-tree -r --name-only "$c"
done | sort -u > /tmp/paths.txt
echo "путей: $(wc -l < /tmp/paths.txt)"
echo "совпадений: $(grep -icE 'review|proposal|report|ревиз|предложен|отчёт' /tmp/paths.txt)"
grep -iE 'review|proposal|report|ревиз|предложен|отчёт' /tmp/paths.txt
```

### 4.3. Метод подсчёта

Число уникальных путей — вывод `git ls-tree -r --name-only` по всем коммитам, достижимым из контрольного SHA, после `sort -u`. Число совпадений — число этих путей, удовлетворяющих `grep -iE 'review|proposal|report|ревиз|предложен|отчёт'`. Регистр не учитывается; поиск идёт по полному пути, а не только по имени файла. Проверка выполняется на полной истории: `git fetch --unshallow origin`, `git rev-parse --is-shallow-repository` → `false`.

### 4.4. Результат по контрольным SHA

| Контрольный SHA | Уникальных путей | Совпадений | Совпадающие пути |
| --- | --- | --- | --- |
| `e192275…` — первая публикация документа | 11 | **1** | `docs/mvp-001-documentation-layout-proposal.md` |
| `a7b6f4e…` — публикация отчёта об устранении замечаний | 12 | **2** | `docs/mvp-001-documentation-layout-proposal.md`; `docs/mvp-001-documentation-layout-proposal-review-response.md` |
| новый HEAD — публикация настоящего отчёта | 13 | **3** | те же два и `docs/mvp-001-documentation-layout-proposal-review-response-followup.md` |

Третья строка — прямое следствие правила 2 раздела 2.1: имя настоящего отчёта содержит `review`, поэтому его добавление закономерно увеличивает число совпадений с 2 до 3. Регрессией это не является: результат предсказан правилом и зафиксирован в таблице.

### Проверки, которые невозможно выполнить

1. **Автоматические проверки репозитория.** В проекте нет приложения, сборки, тестов и workflow CI (`CONTRIBUTING.md`, раздел «Проверки документационного PR»). Обязательные проверки не настроены: `required_status_checks` для `main` равен `null`. Статусов коммита — 0; единственный check run (`Sourcery review`) пропущен. Ни одна проверка не пройдена; успешное прохождение не заявляется.
2. **Воспроизведение исходного мелкого состояния.** `git rev-parse --is-shallow-repository` → `true` относится к исходной рабочей копии; после раскрытия клона команда даёт `false`.
3. **Состояние внешних артефактов Arena.** Файлы `MVP-001-starter-content-proposal-v2.md` и `MVP-001-starter-content-proposal-v2-independent-review.md` находятся вне репозитория и после сброса рабочей среды отсутствуют; по коммиту они не проверяемы.
4. **Собственный SHA коммита.** Итоговый HEAD не может быть указан внутри коммита; подтверждается после публикации командой `git rev-parse HEAD` и по `gh pr view 14 --json headRefOid`.
