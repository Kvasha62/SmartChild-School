# Протокол координации

## Статус и источник

Предложение [BOOTSTRAP-001], подготовленное по [обсуждению №1]. До явного
одобрения владельцем итогового полного commit SHA новые правила предложены,
а не приняты. Одобрение подготовки не является одобрением результата.

Ограничения безопасности из [README](../README.md) обязательны уже сейчас.
Порядок работы с изменениями: [CONTRIBUTING](../CONTRIBUTING.md).

## Участники

- **Владелец проекта** задаёт приоритеты, утверждает требования, принимает
  продуктовые и архитектурные решения, согласует рискованные действия и
  решает, принимать ли конкретную версию изменений.
- **Arena** исследует фактический репозиторий, выполняет согласованные
  изменения, запускает доступные проверки и сообщает результаты и блокеры.
- **ChatGPT** анализирует требования и архитектурные варианты, помогает
  планировать задачи и проводит ревью предоставленных материалов.
  Его рекомендации требуют проверки по реальному коду и требованиям.

Техническое ревью не заменяет решение владельца. Агент не присваивает
собственному предложению статус утверждённого решения.

## Каналы и источник истины

- **Discussion №1** — координация, вопросы, краткие итоги и ссылки на задачи,
  PR и решения. Это не замена очереди задач или документации.
- **Issues** — конкретные задачи с ID, целью, границами и критериями
  готовности. Исходное состояние привязывается к полному commit SHA.
- **Pull requests** — изменения, команды проверок, результаты, ревью и
  решение владельца по точному полному commit SHA.
- **Документация репозитория** — правила и записи решений. Предложенные
  документы явно помечаются; утверждённые решения содержат основание
  согласования по [порядку ADR](decisions/README.md).

Предложение в Discussion не изменяет утверждённые требования автоматически.
При расхождении источников работа в спорной части приостанавливается до
уточнения владельцем. После решения связанные документы обновляются PR.

## Доступ и доставка сообщений

GitHub Discussion используется как доступный общий журнал. Само его
существование не предоставляет ChatGPT доступ к репозиторию и не создаёт
автоматическую связь между агентами.

Пока интеграция не настроена, сообщения передаёт владелец. Arena может
читать журнал и по поручению публиковать сообщения через доступный `gh`.
Постоянное наблюдение, фоновые ответы и автоматическая пересылка в рамках
bootstrap не настраиваются. Это возможная отдельная задача.

Каждое сообщение подписывается `Источник: владелец / Arena / ChatGPT`.
Если текст переслан, сохраняются исходный автор, ссылка и SHA. Сообщение,
опубликованное агентом под общей GitHub-учётной записью, само по себе не
означает решение владельца.

## Формат задачи

```text
Источник:
Задача / ID и ссылка на Issue:
Цель:
Исходное состояние и полный commit SHA:
Затронутые файлы и границы:
Предлагаемое решение (или «не определено»):
Ограничения и что не входит в задачу:
Критерии готовности:
План проверок:
Открытые вопросы и требуемое решение владельца:
```

Форма задачи: [task.yml](../.github/ISSUE_TEMPLATE/task.yml).

## Формат отчёта и ревью

```text
Источник:
Задача / Issue / PR:
Статус: предложено / в работе / на ревью / заблокировано
Полный commit SHA проверяемой версии:
Что обнаружено (факты отдельно от предположений):
Список изменённых файлов и краткое содержание:
Проверки: точные команды, версии инструментов и результаты:
Что не запускалось и почему:
Замечания ревью, риски и блокеры:
Оставшиеся вопросы:
Требуемое решение владельца и следующий шаг:
```

Форма PR: [pull_request_template.md](../.github/pull_request_template.md).

Не называйте запланированную проверку выполненной. При исправлениях
обновляйте отчёт и SHA. Ревью старого SHA не является ревью новых коммитов.
Успешные проверки не утверждают продуктовые или архитектурные решения.

## Принятие результата

1. Исполнитель публикует PR и отчёт по полному SHA.
2. Ревьюер указывает тот же SHA и замечания либо технический вывод.
3. При изменениях повторяются затронутые проверки и ревью новой версии.
4. Владелец явно фиксирует в PR решение по итоговому SHA. До этого результат
   остаётся предложенным. Нет ответа — нет одобрения.
5. Слияние выполняется только по явному решению владельца. Для значимых
   продуктовых и архитектурных решений ведётся отдельная запись ADR.

## Ограничения безопасности

Проект публичный. Не публикуйте секреты и любые персональные данные,
включая реальные данные детей, их учебные работы с такими данными, логи и
изображения. Запрет относится ко всем каналам и вложениям. Примеры и
проверки используют только синтетические данные.

Одобрение обычной задачи не разрешает опасные операции, изменение
production или неоговорённое удаление данных. Для них требуется отдельное
явное согласование. Не передавайте пароли и токены через этот канал.
