### 4.5 Правка 4 · Примечание о ведении таблицы этапов (NC-02) — новая правка

После абзаца, следующего за таблицей этапов (строка 351), добавляется:

```markdown
Таблица этапов ведётся как хроника: строка за очередной этап добавляется следующим изменением либо отдельным PR после завершения этапа, когда известны номер PR и итоговый SHA. Отставание таблицы на один этап от HEAD допустимо и не является неполнотой.
```

**Способ устранения NC-02.** Ревью [PR #24][pr24] предложило выбрать между (а) добавлением строкой для собственного коммита реализующего PR и (б) признанием таблицы растущей хроникой. Принят вариант (б) с уточнением, снимающим оба возражения:

- **неопределённость номера исчезает**: строка добавляется тогда, когда номер PR и итоговый SHA этапа уже известны, — то есть следующим изменением, а не тем же коммитом;
- **неполнота перестаёт быть дефектом**: примечание объявляет отставание на один этап допустимым, поэтому отсутствие строки для HEAD не засчитывается проверяющим как нарушение.

**Правило ПТ-1 (для исполнителя и проверяющих):**

1. Таблица этапов §8 — растущая хроника; каждая содержательная правка документа добавляет одну строку.
2. Строка за этап вносится следующим изменением либо отдельным PR после завершения этапа, когда известны номер PR и итоговый SHA.
3. Требование добавлять строку в том же коммите, который описывается, **не применяется**: оно порождает самоссылку и неразрешимо (номер PR на момент подготовки правки неизвестен).
4. Отставание таблицы на один этап не является неполнотой при наличии примечания из этой правки.

**NC-05 (информационное) — учтено тремя мерами:**

1. **Формулировка.** Утверждение «закрытые PR в GitHub сохраняются неограниченно» заменяется на проверяемое: сохранность подтверждена наблюдением (все ветки с отчётами существуют на `origin`; ветка [PR #13][pr13] сохранена), но не является задокументированной гарантией платформы. Рекомендация `CLOSE WITHOUT MERGE` сохраняется, однако её обоснование не опирается на гарантию.
2. **Сохранение ветвей.** При закрытии [PR #19][pr19]—[PR #22][pr22] ветки `docs/pr14-tr01-fix-report`, `docs/pr14-tr01-rereview`, `docs/pr14-final-verification`, `docs/pr14-merge-report` удалять не следует: сохранность обеспечивается самой ветвью, независимо от поведения служебных ссылок `refs/pull/*`. Проверено: все четыре ветки существуют на `origin`.
3. **Самодостаточность краткой истории.** Поскольку полные отчёты живут только в PR, краткая история в документе должна позволять восстановить суть без обращения к PR.
