## 3. Способ слияния и почему не merge-коммит

Первая попытка — `gh pr merge 14 --merge` — **отклонена репозиторием**:

```
Message: Merge commits are not allowed on this repository.
```

При этом REST-поле репозитория `allow_merge_commit` возвращает `true`. Практический запрет имеет приоритет над значением поля, поэтому способ был изменён.

Выбран **squash** по двум причинам:

1. это единственный из двух оставшихся способов, сохраняющий единый коммит на `main`, — а именно такова вся история `main` (одиннадцать коммитов, у каждого один родитель, в сообщении указан номер PR);
2. `delete_branch_on_merge = false`, поэтому ветка PR и все пять её коммитов сохраняются в репозитории даже после слияния.

**Последствие, зафиксированное как ограничение:** одобренный SHA `9f203708…` не стал предком `main`. Точное дерево одобренной версии сохранено, но сам объект коммита остался только в ветке PR и в `refs/pull/14`. Подробнее — в разделе 7.

## 7. Обнаруженные ограничения

### L-01 · Существенное для воспроизводимости · Способ слияния

Merge-коммит запрещён настройками репозитория, хотя REST-поле `allow_merge_commit` сообщает `true`. Применён squash. Следствия:

- одобренный SHA `9f203708…` **не является предком** `main`; в истории `main` его нет;
- контрольные SHA редакций 2 и 3 — `e192275…`, `a7b6f4e…`, `249af91…` — также **не предки** `main`;
- таблица §2.1, строки 1 и 2 (11 путей / 1 совпадение, 12 / 2), **не воспроизводится из чистого клона `main`**: эти коммиты недостижимы из `main`. Для повторной проверки требуется получить ветку PR либо `refs/pull/14`.

**Ложности это не создаёт.** Правило 1 раздела 2.1 гласит: число совпадений действительно только для указанного контрольного SHA. Документ не утверждает, что названные коммиты являются предками `main`. Объекты коммитов доступны: ветка PR сохранена, GitHub также хранит `refs/pull/14/head`.

**Возможное действие владельца.** Если требуется, чтобы контрольные SHA были достижимы из `main`, необходимо повторное слияние с сохранением истории — то есть пересоздание `main`, что является перезаписью истории и без отдельного решения владельца не выполнялось.

### L-02 · Информационное · Отсутствие автоматических проверок

Автоматических проверок в проекте нет: каталог `.github/workflows` пуст, сборки, тестов и приложения нет; `CONTRIBUTING.md`, раздел «Проверки документационного PR», прямо предписывает не заявлять об их успешном выполнении.

Фактические данные: статусов коммита — 0 (combined status `pending`), обязательные проверки не настроены, ревью и одобрений на PR #14 нет. Единственный check run — `Sourcery review` (приложение `sourcery-ai`) — имеет `status = completed`, `conclusion = **skipped**`: проверка не выполнялась, а не пройдена.

**Успешное прохождение проверок не заявляется.**

### L-03 · Информационное · Эндпоинт защиты ветки недоступен

`GET /branches/main/protection` возвращает `403 Resource not accessible by integration`. Отсутствие обязательных проверок и требований к одобрениям подтверждено косвенно: нулевым числом статусов и check runs, отсутствием workflow CI и отсутствием ревью на PR.

Оно не блокирующее и требует отдельного решения владельца; в рамках настоящей операции не исправлялось.
