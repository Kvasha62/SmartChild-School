- **Место:** `docs/decisions/README.md`, строки 66 и 67 (HEAD `b8a146da…`); строка 68 — «## Порядок ведения».
- **Проблема:** в `main` перед заголовком была одна пустая строка (строка 49); вставка добавила ещё одну, и в файле появились две пустые строки подряд. В остальных местах файла используется одна пустая строка между блоками.
- **Доказательство:** `git diff -U3 c03cda844… b8a146da…` — добавленная пустая строка `+` следует за 17 строками записи, а следующая контекстная строка — уже существующая пустая.
- **Влияние:** косметическое; разметка и содержание не затрагиваются, правила репозитория не нарушены.
- **Рекомендация:** удалить одну из двух пустых строк (строку 66 или 67), либо принять как есть, если владелец считает правку избыточной.
- **Критерий закрытия:** между записью L-02 и заголовком «## Порядок ведения» ровно одна пустая строка.

### NC-32-02 · Низкое · Неточность отчёта о форматировании

- **Место:** отчёт [PR #32][pr32], строка 108 (таблица §5, строка «Форматирование файла») и строка 66 (§4, «Объём»).
- **Проблема:** строка 108 утверждает «записи предшествует пустая строка» — фактически записи (строка 49) предшествует последняя содержательная строка записи OQ-01—OQ-07 (строка 48); пустая строка следует **за** записью. Строка 66 описывает «одну пустую строку перед заголовком раздела», не отражая, что в результате их стало две (NC-32-01).
- **Доказательство:** строки 48—49 и 65—68 файла в HEAD.
- **Влияние:** вводящая в заблуждение формулировка проверки форматирования; на само изменение не влияет.
- **Рекомендация:** при следующем изменении отчёта уточнить формулировки: «записи предшествует последняя строка записи OQ-01—OQ-07; после записи добавлена пустая строка».
- **Критерий закрытия:** формулировки отчёта соответствуют фактическому расположению пустых строк.

### NC-32-03 · Низкое · Не указана область утверждения о слове «принято»

- **Место:** отчёт [PR #32][pr32], строка 102 (таблица §5, строка «Статус записи»).
- **Проблема:** «слово `принято` встречается один раз — в условном предложении…» справедливо для текста записи (1 вхождение), но не для файла: в `docs/decisions/README.md` в HEAD — 7 вхождений (6 было в `main`, добавлено одно — условное предложение строки 63).
- **Доказательство:** подсчёт вхождений `принято` в `main` (6) и в HEAD (7); в записи — 1.
- **Влияние:** неточность формулировки; сам статус присвоен верно.
- **Рекомендация:** указать область: «в тексте записи слово `принято` встречается один раз…; в файле — 7 вхождений, из них 6 существовали ранее».
- **Критерий закрытия:** область подсчёта указана явно.

### NC-32-04 · Низкое · Неполный диапазон PR в основании записи

- **Место:** запись L-02, строка 62: «ревью в PR #19—#25 — 0».
- **Проблема:** утверждение истинно, но диапазон не охватывает открытые [PR #26][pr26]—[PR #32][pr32]; запись тем самым даёт неполную картину проверки.
- **Доказательство:** ревью в [PR #19][pr19]—[PR #25][pr25] — 0; [PR #26][pr26]—[PR #32][pr32] существуют и открыты (ревью владельца в них — 0).
- **Влияние:** информационное; на истинность статуса и выводов не влияет. Изменение текста записи требует отдельного согласования владельца: формулировка утверждена им в версии 5.
- **Рекомендация:** вынести на отдельное решение владельца (вместе с замечанием NC-09 плана); до решения не изменять.
- **Критерий закрытия:** либо владелец подтверждает текущий диапазон, либо утверждает уточнённую формулировку.

### NC-32-05 · Информационное · Фактический результат внешней интеграции не зафиксирован в отчёте

- **Место:** отчёт [PR #32][pr32], §5, раздел «Автоматические проверки».
- **Проблема:** отчёт указывает, что результат внешней интеграции приводится «по факту её завершения», но не фиксирует фактический результат для HEAD. Фактически: `Sourcery review` — `completed`, результат `skipped`; статусов коммита — 0.
- **Доказательство:** GitHub API `commits/b8a146da…/check-runs` и `commits/b8a146da…/status`.
- **Влияние:** информационное.
- **Рекомендация:** при следующем изменении отчёта указать конкретный результат.

**Блокирующих замечаний нет.** Все замечания — низкого уровня или информационные; ни одно не препятствует слиянию [PR #32][pr32] по решению владельца.
