## 2. Метод проверки и команды

Проверка выполнена в отдельном рабочем дереве, созданном от `origin/main`, то есть без опоры на рабочую копию, в которой производилось исправление. Клон полный: `git rev-parse --is-shallow-repository` → `false`.

```bash
# состав PR
git diff --name-status f0253e54dfdbc8e5ce47679ef2c4cfc7adcbc4cf...9f203708d781043b5620e9665eaa6e987939ded9
git diff --name-only  f0253e54dfdbc8e5ce47679ef2c4cfc7adcbc4cf 9f203708d781043b5620e9665eaa6e987939ded9 | wc -l

# объём исправления
git diff --shortstat 249af91c72e81af4c09b6984804f8def24901cb3 9f203708d781043b5620e9665eaa6e987939ded9
git rev-parse 9f203708d781043b5620e9665eaa6e987939ded9^

# имена файлов, извлечённые из формулировки §8, против фактического состава
sed -n '332p' <blob> | grep -oE '`docs/[^`]+`' | tr -d '`' | sort   # против git diff --name-only

# команда из раздела 2.1 проверяемого документа (дословно)
SHA=$(git rev-parse HEAD)
for c in $(git rev-list "$SHA"); do git ls-tree -r --name-only "$c"; done | sort -u
```

Проверяемые файлы извлечены **слепо** из объектов Git (`git show <SHA>:docs/<path>`), а не из рабочей копии. Дополнительно содержимое опубликованного блоба получено через GitHub API и сверено по sha256 с объектом Git.
