## 2. Методология и ограничения проверки

- Данные собраны через GitHub REST API (`gh api`) с полной пагинацией (`per_page=100`): все открытые PR (22 шт.) и все открытые Issues (7 шт., без учёта PR, которые GitHub также возвращает в общем списке Issues).
- Количество открытых объектов мало (22 PR + 7 Issues), поэтому одна страница API (`per_page=100`) покрывает весь перечень — дополнительные страницы не требуются.
- Каждый объект, использованный в выводах, перепроверен по отдельным конечным точкам API (PR detail, PR files, check-runs на HEAD-коммите, ревью).
- Факты, выводы и предположения разделены явно. Статус Draft, successful CI или факт слияния НЕ трактуются как отдельное одобрение владельца.
- Отчёт не меняет `main`, не меняет статусы/labels/assignees/описания существующих PR и Issues, не сливает и не закрывает ничего, не переводит Draft в Ready.
- Недоступные данные (продакшн-окружение, реальный HTTP-ответ сайта, PostgreSQL в среде Arena) отмечены как блокеры, а не подменяются догадками.
