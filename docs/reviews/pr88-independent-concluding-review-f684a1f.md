## 4. Замечания

### F-1. Пункт 8 Issue #79 не представлен дискретно

- **Серьёзность:** незначительная (requirement coverage).
- **Место:** §9 «Предложенный план завершения этапа» (строки 211—236) и §12 (строка 285).
- **Суть:** Issue #79 пункт 8 требует «Один рекомендуемый следующий шаг и альтернативы с кратким обоснованием». Отчёт содержит восьмишаговый план с критериями выхода и точками решений владельца, а также строку «**Следующий шаг:** владелец рассматривает отчёт и даёт решения по пунктам §9 (Шаги 2—7)», но не содержит дискретного «одного рекомендуемого следующего шага + альтернативы с кратким обоснованием». Альтернативы встречаются только внутри шагов 4 (слить на текущем HEAD или исправлять по задаче PR #84) и 6 (закрыть как устаревшие или ре-басить).
- **Доказательства:** Issue #79, пункт 8; §9 и §12 отчёта.
- **Необходимое действие:** добавить дискретный элемент «рекомендуемый следующий шаг + альтернативы с кратким обоснованием» (или явно пояснить, где он реализован).

### F-2. Критерий готовности §12 цитирует CI снимка, а не итоговый HEAD

- **Серьёзность:** умеренная (несовпадение доказательства с утверждением).
- **Место:** §12, строка критерия «Доступные CI/проверки выполнены на точном итоговом HEAD | Да | §11; CI `test` = success на снимке `c8d98f1…`; локальные проверки чистые».
- **Суть:** в строке утверждается, что проверки выполнены на **точном итоговом HEAD**, а в доказательстве цитируется CI на **снимке** `c8d98f177b0f3bd6a0550bf10feef0029aa5e2ec`. Фактически CI на итоговом HEAD `eb4947e…` существует и зелёный (check-run `123636293178`, run `40927350654`), но отчёт его не цитирует.
- **Доказательства:** §12 отчёта; API check-runs для `eb4947e…` и для `c8d98f1…`.
- **Необходимое действие:** либо сослаться на CI итогового HEAD (`eb4947e…`, run `40927350654`), либо скорректировать формулировку критерия так, чтобы она соответствовала приведённому доказательству.

### F-3. Колонка «Файлы» в §3 содержит число, а не перечень файлов

- **Серьёзность:** незначительная (requirement coverage).
- **Место:** §3, колонка «Файлы» (все 26 строк).
- **Суть:** Issue #79 пункт 2 требует «список изменённых файлов» для каждого открытого PR. Колонка содержит только число (в числовом значении встречаются `1` и `4`).

- **Серьёзность:** очень низкая (оформление).
